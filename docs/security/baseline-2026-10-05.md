# Security and development baseline — 2026-10-05

This is an initial source review and local verification, not a penetration test or a statement of absence of vulnerabilities. No runtime source changes, deployment to the user's live agent, Git initialization or publication were performed for the groundwork. Existing installer tests deployed only into temporary test directories.

## Checks actually run

Environment: native Windows, Python 3.12.4; the `bash` found by installer tests reported `/bin/bash` and could not execute a native `C:/…/python.exe` path. No user path or credential is required to reproduce this class of shell mismatch.

```powershell
python -m unittest discover -s tests -t .
python -m benchmark --spaced
```

- Test suite: **125 tests; 121 passed, 3 failed, 1 skipped**; process exit 1.
- Failing tests: `test_installed_hook_runs_end_to_end`, `test_installed_hook_reads_non_latin_content`, `test_installed_hook_protects_secrets`, all in `tests.test_installer.InstallerTest`. Each launcher call returned 127. A UTF-8 decode error in a subprocess reader also appeared. Shell/tool launch compatibility must be resolved, not treated as a detector regression.
- Skipped: the ONNX real-inference test requires a model environment and model files.
- Benchmark: **heuristic-only** because `onnxruntime` was unavailable to this Python interpreter. This run does not measure the installed model-enabled service.

## Limits of this review

The tests execute Python handlers and synthetic fixtures; the installer tests execute a deployed hook in temporary paths. They do not observe Claude Code's actual model requests. No ONNX quality comparison, real-agent canary trace, egress enforcement test, dependency vulnerability scan, secret scan, Git-history audit or private-data inventory was completed here. Those checks are release gates.

The next baseline should retain this record and add new evidence with environment versions rather than editing these results into an apparently passing historical run.
