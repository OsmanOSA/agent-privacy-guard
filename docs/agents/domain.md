# Domain documents

This is a single-context project. Read the root `GLOSSARY.md`, `CONTEXT.md` and relevant `docs/adr/` before drafting a spec or changing an interface.

Use glossary terms consistently. Keep glossary definitions free of implementation details. Record durable trade-offs in concise, sequential ADRs only when alternatives and consequences matter.

Use the product brief for scope, the threat model for security requirements and the architecture document for current interfaces. Flag a conflict with an accepted ADR explicitly. Proposed behavior must remain labeled as proposed until its implementation and evidence exist.
